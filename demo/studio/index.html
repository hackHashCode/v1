How PreCode-JEPA works (as implemented on gagan/precode)

LLM-JEPA adds a loss that makes the model's embedding of a task description predict an embedding of the reference code text. PreCode keeps that recipe and swaps the target for an embedding of what the reference code does when run.

loss = NTP + λ · (1 − cos(W · h_prompt, z_behaviour))
W: linear 2048 → 768 (pred_head.pt), z frozen
precodence: InfoNCE of W·h_prompt against all cached z, τ = 0.07

The target. Each training task's reference solution runs in a sandbox on about 17 probe inputs: its test inputs plus edge cases, one argument changed at a time. Exceptions count as behaviour. The trace lines f(args) -> output are feature-hashed into a 768-number vector. 470 of the 474 training tasks are cached.

The prompt state. h_prompt is the final-layer hidden state at the last prompt token of the ordinary SFT forward pass. Under causal attention it depends only on the prompt, so no extra forward pass is needed and training costs the same as SFT.

At inference nothing changes. Code is generated exactly as with SFT. This studio additionally runs pred_head on the prompt state to show what PreCode "imagined", then executes every program to show what each one actually does.

Why the probe grid matters. Two programs can look almost identical and behave differently. The grid shows every program on the same inputs. With a reference solution, cells are marked right or wrong; without one, rows where the models disagree are highlighted.
